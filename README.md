# TABISAKI — 検索フロー統合プロトタイプ

「まだ知らないワクワクを、自分だけの旅に。」興味を入口に北海道の体験を発見し、公共交通も使う旅を組み立てるFlutter UIプロトタイプです。

## 起動

```sh
flutter pub get
flutter run -d chrome --web-port 7357
```

同じブラウザの同じオリジン（スキーム・ホスト・ポート）で、再読み込み後も設定を復元します。Flutterが起動する一時Chromeプロファイルとは別に、普段のブラウザでアプリの再起動をまたいで保存を確認する場合は、次を実行して `http://localhost:7357` を開いてください。

```sh
flutter run -d web-server --web-port 7357
```

## 操作

1. ホームは「現在選択中の旅行のしおり」です。旅程がある場合は横幅いっぱいの代表写真にタイトル・日程・出発地・移動手段を重ね、写真下部に24px重ねた白いSheetへ訪問順のリストと「旅のしおりを開く」を配置します。写真と主ボタンを固定し、Sheet内のリストだけをスクロールして全スポットを確認できます。旅行がない場合はイラスト・「まだ旅行の予定はありません」・検索開始ボタンを表示し、その下に北海道の体験写真を横スワイプで切り替えられるギャラリーで表示します。写真をタップすると既存の詳細Sheetが下から開き、ストーリーや所要時間を確認・保存できます。左上のメニュー「わたしの旅」から切り替え・名前変更・複製・確認付き削除ができます。スポット0件の保存済み旅程も「作成中」として表示します。「新しい旅を探す」でプロフィールを初期条件として読み込み、既存の3つの好奇心質問へ進みます。旅行がある場合の新規検索はDrawerの「新しい旅を追加」から開始します。プロフィールのプリセット読み込みも、質問から始まります。ホームには検索履歴を表示しません。
2. 質問1は写真付きの4つの気分、質問2は気分別の3択、質問3は写真付きのクエスト3択です。12通りの気分・理由を6種類の好奇心傾向に分類し、5種類のクエストセットを再利用します。質問3の回答後に条件設定へ進み、戻る操作でも回答を保持します。気分を変更すると理由・クエストを、理由を変更するとクエストをリセットします。
3. 全画面の条件設定は、STEP 1「どこから旅を始める？」→STEP 2「どうやって旅する？」→STEP 3「どのくらい旅する？」→STEP 4「誰と旅する？」の順です。出発地は「札幌駅」「新千歳空港」「小樽駅」「旭川駅」の2列×2行の4択で、ワンタップで確定します。検索欄はありません。地図は「地図から選ぶ」を開いたときだけ表示・読み込みし、同じ4地点のピンを選択後「この出発地にする」で確定します。移動手段もカードを1回タップするだけで次へ進みます。
4. 旅行期間は「半日・日帰り・1泊2日・2泊3日以上」の4択をタップすると同行者画面へ進みます。同行者は「ひとり・友達・カップル・家族」の4択。下の折りたたみには片道時間・総予算・徒歩負担をまとめています。最後に「この条件で探す」または「条件を保存して検索」を選びます。後者は任意のプリセット名を入力でき、プリセットとLastSearchを1回の保存処理で更新してから探索へ進みます。キャンセル・保存失敗時は探索を開始しません。スキップ操作はありません。検索フローでは旅行日を聞きません。

5. 探索画面は全10件の写真を事前に読み込みます。最大12秒で個々の失敗をプレースホルダーに確定し、スワイプ中には読み込み直しません。**左スワイプは次へ、右スワイプは保存して次へ**。上スワイプでも保存して次へ進み、ハートは保存・取り消しを切り替えます。最後の次は先頭へ循環します。詳細は長押しまたは画像上のボタンで表示します。
6. カード下の「旅を組み立てる」ボタン、または同名のタブから、保存した体験を追加・削除・ドラッグ並べ替えします。自分で組み立てた旅程とAIのデモ用旅程を表示できます。タブを切り替えても編集中の旅程を保持し、自動保存します。
7. プロフィールでは普段の出発地・交通手段・予算・徒歩希望を保存します。プリセットの読み込み、名前変更、内容編集、上書き、確認付き削除もここから行います。

## 保存と独立性

- `UserProfile`：普段の基本設定。検索中やプリセット編集時の変更は反映しません。
- `SearchPreset`：名前とIDを持つ複数の条件。他のプリセットとは独立しています。
- `InterestAnswers`：気分・興味の理由・クエストの安定したID。検索条件とは別のモデルとして保持します。推薦ではクエストのジャンル、元の気分に近い体験、隣接ジャンル、意外な体験を混ぜ、既存の交通・予算のサンプル評価も利用します。
- `SearchFilters`：既存の不変モデル`SearchConditions`を再利用する型名。出発地・交通・予算などを保持します。
- `LastSearch`：最後に探索へ進んだ条件とUTCの`searchedAt`。旧JSONの`executedAt`も読み込み可能です。
- 検索画面の選択ボタンは初期状態では未選択です。値の初期値は内部に保持し、実際にタップした項目だけ選択表示します。戻る操作では表示を保持し、新しい検索ではリセットします。旅行期間・同行者は明示選択して検索へ進みます。
- 初期値は明示選択プリセット、明示選択した前回条件、通常検索時のプロフィール、デフォルト値の順です。
- 検索実行日時を旅行日には使いません。旅程側の`travelDate`は別のnullable値で、新しい検索では未確定に戻します。旅行日選択は既存の旅程画面で行います。旧プリセットの`dateChoice`/`fixedDate`は互換性のため保持しますが、新しい検索では参照・検証しません。
- [`SharedPreferencesAsync`](https://pub.dev/packages/shared_preferences) とバージョン付きJSONを使用します。WebはlocalStorage、Android・iOSはプラットフォームの設定ストアを利用します。
- 保存処理はRepositoryに分離し、書き込みを直列化します。保存失敗時は成功扱いにせず入力を残します。不正なJSONや読み込みエラーも勝手に初期化・上書きしません。
- 旅程は既存の`TripState`を保存モデルとして再利用し、ID・タイトル・最終編集日時を追加しました。ホームは同じ旅程一覧から表示し、ホーム専用の旅程コピーは保存しません。
- 旅程・保存体験・訪問順・旅行日・条件を`tabisaki.trips.v1`のJSONへ自動保存します。プロフィール等の既存データキーとは分離しています。起動時に両方を復元してからホームを表示します。
- ホームは保存済みの選択IDを最優先します。選択IDが無効なら、今日以降で最も近い旅行、日程未定で最後に編集した旅行、その他の保存済み旅行の順に選び直します。選択IDを保存し、再起動後も過去の旅や作成途中の旅を含めて同じ旅を開きます。最後の旅を削除すると一覧と選択IDを空にします。
- 「旅程を編集する」は表示中の旅程を既存エディターへ渡し、「旅のしおりを開く」は既存の詳細画面を開きます。Drawerの各旅程の「…」から名前変更・独立したコピーの作成・確認付き削除ができます。選択中以外の旅を削除しても現在の表示は変わりません。スポットの削除・並べ替えは既存エディターを利用します。
- 新しい検索の開始だけでは既存旅程を変更しません。検索を実行した時点では別の下書きをメモリ内に保持し、最初のカード保存時に新しい旅程として追加します。既存の保存済み下書きも上書きしません。
- ホームは訪問順だけを表示し、架空の訪問時刻は付けません。日程未定は「日程未定」、公共交通区間は「経路未確認」と明示します。詳細画面の時刻等は従来どおりサンプルです。
- 旅程の書き込みは直列化し、失敗時は画面上部に再試行案内を表示します。読み込みエラー時に保存データを勝手に消しません。
- 質問途中の回答・編集中の検索条件はメモリ内のみです。旅程の永続化は今回から追加しており、過去に再起動で消えた旅程は復元できません。

## 制限・未実装

- AI・交通API・Firebase・認証・課金は追加していません。
- 出発地・交通手段・予算・移動時間などはサンプル推薦のジャンル内順位に反映します。実経路や料金の検索ではなく、条件を満たす保証・除外判定は行いません。
- [flutter_map](https://pub.dev/packages/flutter_map)でパン・ズームできる地図を表示します。地図画像はOpenStreetMapから取得しますが、駅・バス停候補と座標はローカルのサンプルです。外部ジオコーディングや全国の駅検索はありません。検索フローで新しく選べる地点は暫定の4地点です。画像取得失敗時も4択ボタンを利用できます。保存済み条件に別の出発地がある場合は、自動変更せず保持します。地図には出典リンクを表示しています。
- 時刻・乗換・徒歩・交通費・車の所要時間はすべてダミー。帰路や最終便、実際の日帰り可否も検索しません。
- 旅行期間は保存・引継ぎ・表示する段階です。複数日の割当や宿泊施設の予約・検索は実装していません。AI提案も固定の夕張3件を使う「デモ用の旅程」です。
- 観光体験の提供状況・営業時間は未確認。Unsplashの写真も場所を特定しないイメージです。
- 複数タブ・複数端末間の同期や同時編集の競合解決は対象外です。
- Android/iOSの実機ビルドは未検証です。

## 検証

```sh
flutter pub get
dart format .
flutter analyze
flutter test
flutter test --platform chrome test/browser_storage_test.dart test/conditions_steps_test.dart
flutter build web
```

既存のテストには、JSON保存層の復元・独立性・保存失敗・旧日時の移行・UTC・質問先行フロー・条件入力・プロフィールとプリセットCRUDなどの検証があります。画面テストでは地図タイルを無効にし、出発地の4択・地図の開閉・ピンの確認・ズーム・連続タップ・小型Android相当画面も扱います。Chrome専用テストでは実際のWebアダプターで保存・復元を確認します（通常のVMテストではChrome専用の2件をスキップ）。質問・推薦のテストも現在の4×3×3の構成に合わせています。

ホーム・旅程管理のテストでは、選択IDの復元、過去の旅の選択、日程未定・スポット0件、コピーの独立性、削除後の選択、最後の旅の削除、新規検索時の既存旅程保護、Drawer操作と小型Android相当レイアウトを確認します。Android実機での確認は未実施です。
