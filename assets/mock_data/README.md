# 観光地・交通のローカルデータ

Dartの配列ではなく、1件につき1つのMarkdownで管理します。

```text
assets/mock_data/
├── sightseeing_spot/  観光地・体験の .md
├── transit/           交通サンプルの .md
└── images/            写真（jpg / png / webp など）
```

上の3フォルダは `pubspec.yaml` に登録済みです。同じフォルダにファイルを追加するだけで、FlutterのAssetManifestから自動検出します。Dartの一覧や別のindexファイルを編集する必要はありません。新しいサブフォルダを作る場合は、そのフォルダも `pubspec.yaml` に登録してください。

**追加・変更後はアプリを停止して再起動（Web公開時は再ビルド）してください。** 新しいアセットはhot reloadだけでは反映されないことがあります。

この仕組みは開発者が編集する同梱データです。ブラウザからMarkdownファイルを書き換える機能ではありません。プロフィール・検索条件・旅程の端末内保存は従来どおり別で管理しています。

## 観光地を追加する

`sightseeing_spot/` の既存ファイルをコピーし、ファイル名と `id` を変更してください。以下をそのまま雛形にできます。

```md
# 体験のキャッチコピー

- id: new_spot
- order: 110
- area: 北海道の地域名
- category: 自然
- minutes: 60
- access_minutes: 120

## 写真
![代表写真](../images/new_spot.jpg)

## 紹介
一覧カードで伝える短い紹介文。

## ストーリー
ここでどんな発見があるか、好奇心を刺激する紹介文。
段落を分けることもできます。

## 意外な魅力
意外な背景や、別のジャンルにつながる魅力。
未確認の体験はサンプルであることも記載してください。

## 補足写真
![別の角度](../images/new_spot_detail.jpg)
```

- `id` は観光地内で一意にします。既存の `id` を変えると、質問画像や保存済みデータとの関連が変わるため注意してください。
- `order` は表示の基本順です。省略時は1000、同値ならファイル名順です。推薦画面では回答と条件に応じて並び替えます。
- `category` は既存の「食」「歴史」「自然」「街歩き」「ものづくり」「絶景」に合わせると質問との関連がつきます。別ジャンルも探索候補に残ります。
- `minutes` は体験の所要時間の目安です。
- `access_minutes` は札幌から公共交通で向かう場合を想定した、推薦用の仮の片道時間です。省略時は120分。実経路・運行情報ではなく、従来のサンプル評価に使います。
- タイトルは `#`、本文は指定された `##` 見出しで分けます。基本情報は `- key: 値` 形式です。紹介・ストーリー・意外な魅力は必須です。本文はプレーンテキストとして表示します（Markdown装飾を描画する機能はありません）。

## 写真について

写真は画像そのものをMarkdownへ埋め込むのではなく、`![説明](パス)` で参照します。

- ローカル写真：`../images/new_spot.jpg`（Markdownからの相対パス）
- アセットの直接指定：`assets/mock_data/images/new_spot.jpg`
- 外部写真：`https://example.com/photo.jpg`（この場合だけ表示に通信が必要です）

`## 写真` の最初の画像を代表写真、任意の `## 補足写真` の最初の画像を詳細の補足画像として使います。補足写真がなければ代表写真を使います。画像なし・画像取得失敗時は既存のプレースホルダーを表示します。ファイル名に空白や括弧を含めない運用を推奨します。

既存10件の画像は、これまで使っていたUnsplashのイメージ写真を `images/` に保存しています。実際の観光地・施設を撮影した写真であることは確認していません。取得元URLは各Markdownの「写真の出典」に残しています。

## 交通サンプルを追加する

`transit/` に .md を追加します。特定の観光地に向かう区間を登録する場合は `spot_id` にその観光地のIDを指定します。

```md
# サンプルの移動区間

- id: new_spot_bus
- order: 10
- position: any
- spot_id: new_spot
- mode: 路線バス（サンプル）
- departure: 10:00
- arrival: 11:10
- step_minutes: 0
- transfer: 駅前で乗換・待ち時間15分（仮）
- walking: 停留所から徒歩約10分（仮）
- fare: 約800円（仮）

## 注意
サンプル時刻・実際の運行情報ではありません。
運行日・運休・最終便などは未確認です。
```

- `position`：`first` は最初の区間、`following` は2区間目以降、`any` はすべて。
- `spot_id`：到着する観光地のID。`*` は特定の観光地の登録がない場合に使う共通サンプル。
- 対象の `position` に一致する候補の中から、観光地IDが一致するものを優先し、その後に共通サンプルを使います。同じ条件なら `order` 順です。
- 出発地・到着地は、実際の旅程の出発地・前のスポットの地域・到着スポットの地域から表示します。経路が実在することを保証するものではありません。
- `departure` / `arrival` は24時間表記の `HH:mm`。到着が出発より早い時刻なら翌日として扱います。
- `step_minutes` は訪問順の0始まりの番号に掛ける時刻加算です。既存の共通サンプルでは120分ずつずらしています。固定のサンプル時刻を表示する場合は0にしてください。
- `## 注意` は必須で、旅程画面にも表示します。画面共通のサンプル表記は引き続き表示します。
- 交通にも任意の `## 写真` を記録できますが、現行の交通カードでは画像を表示しません。
- 該当サンプルがない区間は「交通サンプル未登録」「未確認」と表示します。存在しない便を自動生成しません。

## エラーと将来の保存先

必須項目の不足・IDの重複・不正な時刻は、ファイル名付きの読み込みエラーにします。データを黙って破棄したり、保存済み旅程を消したりはしません。

データの取得は `MockCatalogRepository`、Markdownの実装は `MarkdownMockCatalogRepository` に分離しています。将来Firestoreへ移す際はRepositoryの実装を差し替え、既存のExperience・画面・推薦処理は再利用できます。現時点でFirestoreには接続していません。
